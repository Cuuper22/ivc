## Positive Model

Best live positive reading:

`002-390-X` is a fixed construction with a paradigmatic slot after `002-390`.

That does not mean a translation is accepted. It means something narrower: the branch signs should be tested as a closed-choice system — a small fixed menu of options — that may condition syntax, semantic class, or following structure.

Ranked positive hypotheses:

| rank | hypothesis | why live | translation-system consequence if proven |
|---:|---|---|---|
| 1 | syntactic/semantic selector after fixed stem | Same stem followed by a small branch set is what a productive construction can look like. | Model `002-390` as a frame and force `X` to control downstream class/role. |
| 2 | argument-role or case-like branch | Branch choice may track what kind of participant or complement follows. | Gloss by constructional role, not flat sign value. |
| 3 | interrogative/choice-operator family | Fixed frame plus branch options could mark requested answer/slot type. | Treat branches as question/choice operators if context supports it. |
| 4 | classifier/category selector | Branch may classify the semantic domain of the following item. | Propagate category constraints forward from `X`. |
| 5 | inflectional morphology on `002-390` | Possible only if branches are mutually exclusive and bound-like. | Collapse `002-390-X` into inflected forms of a construction. |
| 6 | scribal/formal variant system | Weakest positive language read, used only if contextual tests fail. | Demote from semantic grammar to formal/register variation. |

Key prediction:

If each branch has a distinct following-context profile, the translation system should encode `002-390-X` as branch-conditioned grammar. If branch signs behave similarly outside this frame, they may be independent operators rather than endings. If they occur only here, a bound-construction analysis strengthens.

## Adversarial Model

Strongest attack:

`002-390-X` is a copied visual-register template whose branching is produced by source clustering, positional anchoring, tail-space completion, and catalog over/under-splitting.

Adversarial hypotheses:

| attack | mechanism | what it would explain |
|---|---|---|
| copied template stem | Shared source exemplar or workshop/copy family repeats `002-390`; endings drift locally. | Branching without productive language behavior. |
| register template | `002-390` is an administrative/emblematic frame, with `X` as controlled register/identity fill. | Low-language label behavior, not open script grammar. |
| source-window artifact | Cropping/damage makes `002-390` the first stable visible block. | Apparent branch starts where preservation diverges. |
| positional layout | `002-390` is a stable edge/field anchor. | Following signs determined by line position and space. |
| tail-space filler | Terminal signs fill remaining visual room. | Closure/continuation tracks physical layout, not syntax. |
| catalog conflation | `002` or `390` merges distinct signs, or `X` over-splits variants. | False parent category and false branch diversity. |

## Concession Tests

The adversarial model concedes real script behavior if the branch system survives:

1. Independent recurrence across unrelated sites, media, object types, hands, and archaeological contexts.
2. Blind segmentation stability for `002`, `390`, and the following boundary.
3. Position independence after controlling for edge proximity, tail space, object shape, and adjacent imagery.
4. Substitution discipline: the `X` slot excludes visually plausible alternatives.
5. Bidirectional distribution: branch signs behave systematically outside `002-390-X`.
6. Error/confusion patterns consistent with sign identity, not ornamental drift.
7. Cross-template compositionality: `002`, `390`, and `X` each add predictive behavior.
8. Catalog robustness under aggressive recoding, merging, splitting, and damaged-case removal.
