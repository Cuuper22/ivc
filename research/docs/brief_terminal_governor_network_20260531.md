# One-page brief: terminal-governor network in the Indus corpus

Evidence level: promoted candidate, not accepted. No sound value, translation, or language identification is claimed.

## Claim

The strongest current frontier result is a structural one: signs `002` and `060` behave like terminal governors. They take small inventories of immediately following closure signs at the end of formulaic units. The shared closure sign is `820`.

Smallest model:

- Hardest-block core: `002->{817,820}` and `060->920`
- Global extension: `060->{550,820}`, `060-692`, and leaky `002-861`
- `741/742/745` is a syntactic alloseries selecting the marked `060-920` closure

This is not a decipherment. It is a slot-function reading: these signs are behaving like operators in a constrained terminal grammar.

## Why it is hard to dismiss

In exact-collapsed cells, the core edges are large and terminal-heavy:

- `002-817`: 108 exact cells, 105 terminal
- `002-820`: 75 exact cells, 70 terminal
- `060-920`: 52 exact cells, 51 terminal
- `060-550`: 24 exact cells, 23 terminal
- `060-820`: 23 exact cells, 23 terminal

The same graph survives hostile controls:

- Terminal-label shuffle: p=0/5000 for live edge count, multi-governor count, shared-closure count, and exact target shape.
- Row-internal order forger: p=0/2000 while preserving each inscription's sign multiset.
- Leave-site stress: strict edges survive removing Mohenjo-daro or Harappa.
- Object-level edge dedupe: the graph survives when each CISI/object contributes at most one count per edge.
- Text-family collapse: the graph survives when each exact inscription text contributes at most one count per edge; terminal shuffle still gives p=0/5000 for the target shape.
- Penult-final independence null: preserving penultimate signs and shuffling final signs across 2,127 terminal text families gives p=0/5000 for the target shape.
- Local source spot audit: one available source image per live edge was checked; no immediate contradiction found for the catalogued terminal clusters.
- Direction reversal: the target graph is not reproduced by reversing rows.

The hardest stressor so far is removing Mohenjo-daro `SEAL:S`. The core survives (`002-817`, `002-820`, `060-920`), but the lower-support `060-550/820/692` branches fall below the `n>=20` strict floor. That support-limits the full five-edge shape under the harshest block; it does not reverse the terminal behavior.

Removing weak object/site identity rows does not hurt the model: the same strict/near split remains.

The selector subclaim is sharper: `741/742/745` appears before `060-920` in 40/52 object-collapsed cells and before sibling caps `060-692/550/820` in 0/84 cells. Text-family collapse gives 39/51 and 0/76. It survives leaving out Mohenjo-daro or Harappa. Cap-label shuffle gives p=0/5000.

## What was killed

The result is not a broad visual cap-family claim. Blind source packets support visually distinctive `060-920` and weakly support one `060-820` case, but do not make `692` or `550` look like shared graphic cap variants.

The result is not a sound value for `820`. A wheel/rosette source-peek is promising for `820` as a portable closure sign, but the prior Brahmi-value route is blocked.

The result is not a claim that `741/742/745` are one proven graphic allograph. A source peek supports the cluster as real, but the conservative live model is three catalog signs sharing one syntactic feeder role.

The result is not a Meluhha bilingual. `407` still has a strong internal copper/rectangular-register signal and weak external semantic convergence with cuneiform Meluhha copper contexts, but no object-level external bridge.

## Current status

Promote the terminal-governor model and the `741/742/745 -> 060-920` selector above ordinary candidate status. Do not enter them as accepted until a token-boxed stratified source audit and a stricter graphic/source-family null both survive.
