# Lipi 390/405/406/407 / Mayig P086 merge gate

Date: 2026-07-12 America/Los_Angeles

Decision: `SOURCE_VISIBLE_NONINJECTIVE_NAMESPACE_MERGE_ACCEPTED_FOR_EXPLICIT_MAYIG_POLICY_ONLY`.

Scope: observed Lipi numeric signs `{390, 405, 406, 407} -> mayig_p:P086`.

## What this is and why it exists

Sometimes one catalogue draws finer distinctions than another. Lipi, the numeric catalogue, has four separate numbers for tree-like signs: `390`, `405`, `406`, and `407`. Mayig, the Parpola-style catalogue, has one code covering all of them: `P086`. That is a merge, an edge where several signs in one catalogue map to a single sign in the other.

A merge is only safe when you know it is a merge. Used carelessly, it silently erases four distinctions and then any pattern you find might just be an artifact of the collapsing. This gate accepts the edge, but fences it into one clearly labeled analysis lane, a run that declares up front which sign policy it is using, so that no result can quietly inherit Mayig's coarser grouping.

This is a many-to-one bridge between catalogue namespaces. It is not an exact or bidirectional sign identity, not an instruction to collapse the raw Lipi inventory, and not a sign meaning, reading, phonetic value, language identification, or translation.

## Alignment pressure

Alignment pressure is the case for the mapping: how often each label lands on the same position of the same object.

The pinned positional alignment table contains 29 P086 positions:

| Lipi sign | P086 positions | Share of reverse P086 lane | Observed objects |
| --- | ---: | ---: | --- |
| 390 | 25 | 0.862069 | 24 distinct; M-131 occurs twice |
| 405 | 2 | 0.068966 | M-34; M-172 |
| 406 | 1 | 0.034483 | M-170 |
| 407 | 1 | 0.034483 | M-171 |

A lane is one direction of the mapping, and the two directions behave very differently here. Going forward from `390` to `P086`, every one of the 25 occurrences agrees: 25/25 with no counterexample. Going backward from `P086` you land on four different Lipi numbers. That reverse lane is non-injective, meaning several distinct inputs share one output, so the mapping cannot be undone. Knowing a sign is `P086` does not tell you which of the four Lipi signs it was. A clean forward lane is therefore not enough to call the relation exact.

The tree-family forms visibly differ in branch structure, which is the point: Mayig does not pretend P086 is a single featureless shape. Alongside the code it stores a feature vector, a fixed list of measured attributes attached to the sign. For P086 that vector records branch factor, branch count, branch direction, and final-branch shape. The distinctions Lipi puts in separate numbers, Mayig puts in those fields. The dominant-390 packet covers initial, medial, and terminal positions, so the evidence is not confined to one part of an inscription.

## Pinned Mayig evidence

Pinned means the evidence is read from one fixed commit, so the record cannot shift under the decision later.

Mayig commit: `ad2f1e218a34b8c33c57de0d6cb8d99272765bbb`.

`features/P086.json` describes P086 as a simple tree with branches at the top and keeps four custom branching features. Its mediated Wells list, meaning the Wells-catalogue identifiers Mayig associates with the code, is `W390`, `W392`, and `W405-W408`. That list is an independent warning from the catalogue itself: P086 is a bucket for a family of forms, not a one-to-one identifier.

The eight pinned object records place P086 at the same stored position as the corresponding Lipi sign. Their exact raw-file hashes are recorded in `evidence_refs.csv`.

Local signs `392` and `408` appear in that Wells list but were never observed in the alignment data, so they are not promoted. A mediated Wells list inside Mayig is not evidence that local numeric labels and Wells identifiers are interchangeable.

## Analysis policy

The whole point of accepting this edge is to keep it visible wherever it is used.

- Raw Lipi analyses keep `390`, `405`, `406`, and `407` distinct.
- `conservative_merge`, the policy that uses only exact or very high-confidence allograph edges, does not use this cluster at all.
- A run that explicitly declares itself a Mayig/Parpola-policy lane may map the four source-bound Lipi members to P086, provided it keeps the P086 feature vector rather than discarding it.
- The existing `390/405` collision adversary still governs the `002-390-X` ecology. This gate is not a licence to inflate or collapse that branch family.
